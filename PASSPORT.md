## §0. ЖЁСТКИЕ ПРАВИЛА РАБОТЫ (обязательны к исполнению)

### 0.1 Принцип "Не изобретай велосипед"
**ПРИ СОЗДАНИИ НОВОГО КОНТЕЙНЕРА С АНАЛОГИЧНЫМ СТЕКОМ:**
1. Сначала `docker inspect prostors_app` — извлечь конфигурацию (образ, сеть, env, volumes, command, DNS)
2. Скопировать 1:1, заменить только специфичное (токен бота, имя контейнера, папку кода, БД)
3. Запустить — не должно быть проблем, потому что стек идентичен рабочему
4. **НЕ изобретать свою конфигурацию с нуля** — это нарушение принципа "факты до диагноза"

### 0.2 Правило STOP
- **Любое отклонение от паспорта = СТОП и варианты владельцу ДО выполнения**
- Нельзя "лечить симптомы" без отчёта о фактах
- Нельзя перебирать подходы самостоятельно
- Факты (SELECT/curl/docker inspect) ДО диагноза, не после

### 0.3 Правила работы (из ProStors)
- `.env` править только явной командой; после каждого изменения `grep -c` по файлу; секреты через `read -r K` (в историю не падает)
- `node` на хосте НЕТ — проверка синтаксиса только через `docker run ... --entrypoint node --check`
- Факты до диагноза: если "не работает" — сначала SELECT/curl/docker inspect, потом диагноз
- Длинные вставки — ТОЛЬКО файлом (nbsp/CRLF из чата ломают код), в PuTTY короткие плоские команды
- После правки статики — bump `?v=` (свои правила кэша — свои строки версий)
- Числовые поля формы → `null`, не `''`
- R24: не обещать несуществующее (в оффере знакомому НЕ обещать до готовности)

### 0.4 Принцип "Дураку полдела не показывай"
Знакомый НЕ знает о проекте, пока не показано готовое демо. Никаких "почти готово", "ещё немного" — только работающий продукт.

**Таблица `products`:**
```sql
CREATE TABLE products (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    tenant_id INTEGER DEFAULT 1,
    article TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    category TEXT,
    brand TEXT,
    price REAL NOT NULL,
    stock INTEGER NOT NULL DEFAULT 0,
```

### 5.3 Nginx (требует настройки)

**Требуемый server-блок (только по явной команде владельца):**
```nginx
server {
    listen 443 ssl;
    server_name zap.prostors.ru;
   
    ssl_certificate /etc/letsencrypt/live/zap.prostors.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/zap.prostors.ru/privkey.pem;
   
    location / {
        proxy_pass http://zap_app:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

⚠️ **ПРАВИЛО:** Nginx server-блок добавлять ТОЛЬКО по явной команде владельца. До этого — не трогать.
